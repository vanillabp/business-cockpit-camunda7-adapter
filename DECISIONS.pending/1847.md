# The delete reason of a cancelled process instance is the comment, unless the engine wrote it itself

Decided on 2026-11-13 by the maintainer.

## What the extension does

The prefill of the report about the end of a process instance carries the instance's delete reason as
its comment. The prefill of the report about a deleted user task carries the task's delete reason. A
details provider which sets a comment of its own replaces it.

## Why the text of the reason decides

The engine fills the same field on its own: `completed` for a completed task, `deleted` for a task
whose instance is deleted without a reason, and sentences like `Interrupting activity ... executed.`
for a boundary event, an event subprocess, a migration, a process instance modification or a
multi-instance completion condition. None of these is a reason a person gave, and a modelled path out
of a task is the normal end of business.

Nothing else tells the two apart. The engine deletes the tasks of an instance before it marks the
instance as deleted, so the task listener sees an instance which looks as if nothing happened to it.
So `Camunda7DeleteReasons` knows the texts Camunda 7.24 writes and leaves them out. A text a later
engine adds reaches the cockpit as a comment until it is added there. A reader sees that at once, and
it harms nothing else.
